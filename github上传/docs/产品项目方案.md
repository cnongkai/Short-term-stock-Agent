# 短线股票推荐 Agent — 产品项目方案

> **版本**: V2.1  
> **更新日期**: 2026-07-13  
> **产品定位**: A 股短线股票自动化每日推荐系统

---

## 一、产品概述

### 1.1 产品定位

基于 LangGraph 多智能体编排的 A 股短线推荐系统，通过**发现层 → 分析层 → 决策层**三阶段流水线，每日输出 2-11 只短线候选标的（主线热门板块选股 5-8 只 + 支线黑马扫描 0-3 只）。

### 1.2 目标用户

| 用户画像 | 核心诉求 | 产品价值 |
| --- | --- | --- |
| 短线交易者 | 每日精选标的、节省选股时间 | 自动化全链路分析，15 分钟出结果 |
| 量化爱好者 | 可追溯的决策逻辑、数据驱动 | 五维量化赋分 + 全链路留痕 + 验证报告 |
| 投研学习者 | 理解多 Agent 协作与 ReAct 模式 | 透明的推理过程 + 工具调用日志 |

### 1.3 核心能力

- **四路并行发现**: 新闻/情绪/政策分析师 + 板块推理同时运行
- **五维量化赋分**: 热度/扩散力/动摇度/回补力/拥挤度，纯算法无 LLM 依赖
- **拥挤度地图**: Top 10 板块 5 级颜色梯度可视化
- **双路选股**: 主线热门 + 支线黑马并行，覆盖不同收益结构
- **四维 ReAct 分析**: 基本面/技术/A股专属/个股发展，每只股票 4 维深度分析
- **多空辩论决策**: Bull vs Bear 研究员 + 三风格风控（激进/保守/中立）
- **全链路留痕**: 完整状态日志 + 运行验证报告 + 指标 JSON
- **数据源熔断器** (V2.1): provider+method 级别熔断 + HALF_OPEN 渐进退避，避免对不可用 API 反复重试
- **LLM 安全调用** (V2.1): safe_llm_invoke 90s 硬超时 + 重试 + 降级，消除分析层卡死
- **SKILL 六段提示词** (V2.1): 18 个 agent 统一【角色/设定/目标/SKILL/输出/限制】结构，注入短线趋势/催化/风险/误区
- **板块BK动态映射** (V2.1): 替代死列表，从东财实时获取板块名→BK代码映射，push2 fallback 覆盖率 ~100%

### 2.2 V2.1 版本更迭目的

#### 核心目标

在 V2.0 四路并行架构基础上，解决端到端运行暴露的三类问题：
1. **数据源容错不足**: AkShare RemoteDisconnected 频发导致 get_stock_info 全链失败、Sina fallback SSL 握手挂死 60s+
2. **LLM 调用无保护**: 14 处裸 `llm.invoke()` 无超时无降级，分析层可能永久阻塞
3. **Prompt 缺乏短线导向**: agent 提示词无统一结构，缺乏短线趋势/催化/风险 SKILL，易陷入长线价值投资误区

#### 更迭动机

| 问题 | V2.0 现状 | V2.1 改进 |
| --- | --- | --- |
| **数据源全链失败** | 无熔断, 同一 provider+method 反复重试 | provider+method 级熔断器 (3 次失败→120s 冷却→HALF_OPEN→渐进退避 2x/4x) |
| **Sina fallback 挂死** | akshare `stock_zh_a_daily` 内部 requests 无 timeout, SSL 握手 60s+ | `_call_with_hard_timeout` ThreadPoolExecutor 强制 30s 硬超时 |
| **LLM 调用阻塞** | 14 处裸 `llm.invoke()`, 无超时无降级 | `safe_llm_invoke`: 90s 硬超时 + 瞬时错误重试(2次/指数退避) + FallbackResponse |
| **Prompt 无短线导向** | 18 个 prompt 结构不一, 无 SKILL 注入 | 六段结构(角色/设定/目标/SKILL/输出/限制) + 4 个共享 SKILL 常量(趋势/催化/风险/误区) |
| **板块BK死列表** | `_SECTOR_BK_MAP` 含重复 BK 代码+缺失板块, push2 覆盖率 ~30% | 从 `stock_board_industry_name_em` 动态获取并缓存, 覆盖率 ~100% |
| **技术指标类型异常** | 数据源返回字符串 OHLCV, RSI/KDJ 计算抛 'str'-'str' | `pd.to_numeric(errors='coerce')` 强制类型转换 + dropna |
| **板块推理死列表** | `_get_static_sectors()` 返回 8 个假板块(编造涨跌幅/资金流) | `_get_historical_sectors()` 从 `sector_scores_history.json` 读取历史均值 |

### 2.3 V2.0 版本更迭目的

#### 核心目标

将板块推理从"三路分析师的下游串行节点"重构为"第四路并行节点"，从 LLM 评分改为纯量化五维赋分。

#### 更迭动机

| 问题 | V1 现状 | V2 改进 |
| --- | --- | --- |
| **执行效率** | 板块推理等待三路分析师完成才启动，串行瓶颈 | 四路并行，板块推理与分析师同时运行 |
| **评分稳定性** | LLM 四维评分，结果不稳定且依赖 prompt 质量 | 纯量化五维算法，结果可复现 |
| **LLM 成本** | 板块推理消耗一次 LLM 调用 | 零 LLM 调用（纯算法） |
| **数据维度** | 仅基于热点话题推理 | 资金面 + 注意力双维度搜索指数 |
| **可视化** | 仅 ranked_sectors 列表 | Top 10 拥挤度地图 + 5 级颜色梯度 |
| **趋势追踪** | 无历史对比 | 日环比（历史分数持久化 30 天） |

## 三、解决的问题

### 3.1 技术问题

#### 问题 1: 串行瓶颈导致执行耗时过长

**V1 架构**:
```
START → News/Sentiment/Policy (并行) → Sector Inference (串行等待) → Stock Selector
```
板块推理必须等待三路分析师全部完成，导致发现层耗时 = 三路最长耗时 + 板块推理耗时。

**V2 解决方案**:
```
START → News/Sentiment/Policy/Sector Inference (四路并行) → fan-in → Stock Selector
```
利用 LangGraph fan-in 语义，双路选股节点等待全部 4 路完成。发现层耗时 = max(四路耗时)，消除串行等待。

#### 问题 2: LLM 评分不稳定

**V1 问题**: 板块推理使用 LLM 进行四维评分，同一输入不同运行可能得到不同结果，难以复现和调试。

**V2 解决**: 改为纯量化算法，五维指标基于资金面数据（AkShare/BaoStock）和注意力数据（Bing 搜索）计算，结果完全可复现。

#### 问题 3: 数据源故障导致流程中断

**V1 问题**: AkShare RemoteDisconnected 错误导致板块推理获取不到数据，流程卡死。

**V2 解决**:
- 三级 fallback: AkShare → Tushare → BaoStock
- 历史均值兜底（从 `sector_scores_history.json` 读取，非编造数据）
- 注意力获取失败时降级为 0 分（不阻塞流程）
- **V2.1 新增**: provider+method 级熔断器 + Sina fallback 硬超时 + 板块BK代码动态映射

### 3.2 产品问题

#### 问题 4: 缺乏板块拥挤度可视化

**V1 问题**: 仅输出 ranked_sectors 列表，用户无法直观感知板块拥挤程度。

**V2 解决**: 输出 Top 10 板块拥挤度地图，5 级颜色梯度映射：
- 🔴 ≥80 极度拥挤 → 警惕追高风险
- 🟠 60-79 拥挤 → 谨慎参与
- 🟡 40-59 适中 → 正常关注
- 🟢 20-39 宽松 → 适合布局
- 🔵 <20 极度宽松 → 关注但未启动

#### 问题 5: 缺乏趋势追踪能力

**V1 问题**: 无法对比板块热度变化趋势。

**V2 解决**: 历史分数持久化（`results/sector_scores_history.json`，保留 30 天），每次运行计算日环比变化率（如 "+5.2%" / "-3.1%"）。

#### 问题 6: 分析师工具单一依赖 AkShare

**V1 问题**: 分析师仅依赖 AkShare 数据源，故障时无法自服务获取数据。

**V2 解决**:
- 新增 `web_search` 工具（Bing 搜索，国内可用）
- 新增 `realtime_quote` 工具（新浪实时行情 API）
- 分析师提示词增加"自救工具"指南
- 工具数从 8 个扩展到 10 个

## 四、产品优势

### 4.1 架构优势

| 优势 | 说明 |
| --- | --- |
| **四路并行** | 发现层 4 路并行执行，最大化利用并发能力，缩短整体耗时 |
| **fan-in 同步** | LangGraph 原生语义保证数据一致性，无需手动同步 |
| **状态隔离** | 并行节点写入不同状态字段（单写者模式），无并发冲突 |
| **向后兼容** | V2 输出兼容 V1 的 ranked_sectors 格式，下游无需改动 |

### 4.2 量化优势

| 优势 | 说明 |
| --- | --- |
| **纯量化赋分** | 五维指标基于客观数据计算，无 LLM 随机性 |
| **可复现** | 相同输入必然得到相同输出，便于回测和调试 |
| **可配置** | 五维权重可通过配置文件调整（`sector_metric_weights`） |
| **可追踪** | 历史分数持久化，支持日环比趋势分析 |

### 4.3 工程优势

| 优势 | 说明 |
| --- | --- |
| **多级容错** | 数据源三级 fallback + 历史均值兜底 + 注意力降级 + 熔断器 + Sina 硬超时 |
| **LLM 安全** | safe_llm_invoke 90s 硬超时 + 重试 + 降级, 消除分析层卡死 |
| **全链路留痕** | 完整状态 JSON + 运行验证报告 + 指标数据 |
| **107 项测试** | 9 冒烟 + 31 板块 + 18 并行 + 13 熔断器 + 12 LLM + 24 技术指标，覆盖核心逻辑 |
| **阶段计时** | 关键节点阶段级耗时日志，便于排查性能瓶颈 |

## 五、埋点设计

### 5.1 埋点分层架构

```
┌───────────────────────────────────────────────────────┐
│                    埋点分层架构                         │
├───────────────────────────────────────────────────────┤
│                                                       │
│  L1: 节点级埋点 (RunMetrics.node_timer)               │
│  ├── 各节点入口/出口时间戳                              │

│  └── 写入 node_timings → 验证报告                      │
│                                                       │
│  L2: 阶段级埋点 (log_stage)                            │
│  ├── 节点内部各阶段耗时 (INFO 日志)                     │
│  ├── 阶段产物摘要 (result)                             │

│                                                       │
│  L3: LLM 调用埋点 (RunMetrics.llm_timer)              │
│  ├── LLM 调用耗时                                      │

```

### 6.2 四路并行数据流

```
START
  │
  ├──→ 新闻分析师 ──────→ hot_topics (operator.add) ──────┐
  ├──→ 情绪分析师 ──────→ hot_topics (operator.add) ──────┤
  ├──→ 政策分析师 ──────→ hot_topics + policy_events ─────┤ fan-in
  └──→ 板块推理(V2) ────→ ranked_sectors + crowding_map ──┘ 同步
                                    │
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
              主线选股                          黑马扫描
          (读 ranked_sectors              (读 ranked_sectors
           + hot_topics)                   排除热门板块)
                    │                               │
                    └───────────┬───────────────────┘
                                ▼
                         候选池合并 (去重 + 熔断)
                                │
                                ▼
                         分析层 (四维 ReAct)
```

## 八、风险与应对

### 8.1 技术风险

| 风险 | 概率 | 影响 | 应对措施 |
| --- | --- | --- | --- |
| AkShare 全部接口故障 | 中 | 板块数据缺失 | 三级 fallback + 历史均值兜底 + 熔断器渐进退避 |
| Bing 搜索被限流 | 低 | 注意力分数缺失 | 降级为 0 分（不阻塞流程） |
| LLM 调用超时 | 中 | 分析层卡死 | safe_llm_invoke 90s 硬超时 + 重试 + FallbackResponse |
| Sina fallback SSL 挂死 | 中 | 单次 fallback 60s+ | `_call_with_hard_timeout` 30s 硬超时 |
| 并行状态写冲突 | 低 | ConcurrentUpdateError | 单写者模式 + operator.add |
| 历史分数文件损坏 | 低 | 环比计算失败 | try-except 降级为 "N/A(首次)" |
| 板块BK代码过期 | 低 | push2 fallback 失效 | 动态从 `stock_board_industry_name_em` 获取并缓存 |

### 8.2 业务风险

| 风险 | 应对措施 |
| --- | --- |
| 大盘暴跌 (>4%) | 熔断机制暂停推荐 (circuit_breaker) |
| 候选池为空 | 降级输出空推荐 + 告知用户 |
| 板块全部低分 | 仍输出 Top N（按分数排序），拥挤度地图反映冷淡 |
